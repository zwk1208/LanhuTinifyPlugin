# Lanhu Resource Assistant 插件使用说明

本文档面向第一次使用插件的用户，介绍安装、前期配置、蓝湖信息获取、图片导入和最终写入 Android 工程的完整流程。

## 一、安装插件

1. 使用 Gradle 构建插件：

   ```powershell
   .\gradlew.bat test
   .\gradlew.bat buildPlugin
   ```

2. 打开 Android Studio 或 IntelliJ IDEA，进入：

   **Settings/Preferences → Plugins → 齿轮 → Install Plugin from Disk**

3. 选择：

   ```text
   build\distributions\LanhuResourceAssistant-1.0.0.zip
   ```

4. 按提示重启 IDE。
5. 通过 **View → Tool Windows → Lanhu Resource Assistant** 打开插件工具窗口。

## 二、前期配置

插件有两类可选配置：

- 蓝湖登录 Cookie：用于从蓝湖设计稿链接读取图片。
- Tinify API Key：用于压缩勾选了“需要压缩”的图片。

只使用本地图片或 ZIP 导入时，不需要配置蓝湖登录 Cookie；不勾选任何图片的“需要压缩”时，也不需要 Tinify API Key。

### 1. 获取 Tinify API Key

如果需要压缩图片：

1. 打开 [TinyPNG Developer API](https://tinypng.com/developers)。
2. 注册或登录 Tinify 账号。
3. 在开发者页面创建或查看 API Key。
4. 复制 API Key，回到插件工具窗口。
5. 在“Tinify API 配置”区域粘贴到 API Key 输入框。
6. 点击“保存密钥”。

API Key 使用 IntelliJ Platform 的 `PasswordSafe` 保存，不会写入项目文件，也不会输出到日志。不要把 API Key 提交到 Git、写入 `README` 或发送给他人。

Tinify 按账号额度和官方计费规则处理请求。插件每批最多处理 20 张图片；如果图片数量较多，需要分批执行。

### 2. 获取蓝湖 Cookie

蓝湖设计稿接口通常需要已经登录并且有项目访问权限的浏览器 Cookie。插件不会抓取蓝湖网页 DOM，而是使用你提供的登录 Cookie 调用蓝湖接口。

获取步骤：

1. 使用浏览器打开蓝湖链接并完成登录。
2. 如果页面提示加入团队、输入分享密码或申请权限，先在浏览器中完成。
3. 按 `F12` 打开开发者工具。
4. 在 **Network/网络** 面板刷新蓝湖页面。
5. 找到一个发往 `lanhuapp.com` 的请求。
6. 打开请求详情，在 **Request Headers/请求标头** 中找到 `Cookie`。
7. 复制 Cookie 整行内容，格式通常类似：

   ```text
   key1=value1; key2=value2; ...
   ```

8. 将内容粘贴到插件“蓝湖登录 Cookie”输入框。
9. 点击“保存 Cookie”。

Cookie 具有登录权限，不能公开发布。Cookie 过期、账号退出登录、团队权限变化或蓝湖服务端更新后，可能需要重新复制并保存。

> 不要复制浏览器地址栏中的 `blob:` 图片地址。`blob:` 地址只在生成它的浏览器标签页中有效，插件无法跨进程读取。

## 三、蓝湖链接格式

插件支持以下两类蓝湖地址。

### 1. 项目分享链接

常见格式：

```text
https://lanhuapp.com/link/#/invite?sid=...
```

项目分享链接会读取该项目中可访问的设计稿页面和切图。

### 2. 单页面详情地址

常见格式：

```text
https://lanhuapp.com/web/#/item/project/detailDetach?type=image&pid=...&teamId=...&project_id=...&image_id=...
```

单页面详情地址通常需要包含：

- 项目参数：`pid`、`project_id` 或 `projectId`
- 团队参数：`tid`、`team_id` 或 `teamId`
- 页面参数：`image_id`、`imageId`、`doc_id` 或 `docId`

详情地址只读取指定页面，不会列出整个项目。缺少必要项目或团队参数时，插件会提示缺少的参数。

蓝湖链接输入框支持：

- 每条链接单独占一行；
- 一次粘贴多个项目或页面链接；
- 粘贴蓝湖复制出来的包含说明文字的整段内容，插件会自动提取其中的 URL；
- 使用“清空”按钮清除当前输入内容。

## 四、从蓝湖设计稿导入

1. 在“导入设置 → 蓝湖链接导入”中填写蓝湖链接。
2. 确认已经保存蓝湖 Cookie。
3. 如有需要，在“蓝湖回退 density”中选择默认回退值，默认是 `xxhdpi`。
4. 点击“读取设计稿…”。
5. 插件会依次读取链接、页面和切图，并在“设计稿读取状态”处显示当前进度。
6. 多个设计稿会汇总到同一个选择窗口，不会为每个设计稿重复弹窗。
7. 在选择窗口中勾选需要导入的图片。
8. 根据需要选择：
   - 图片格式：PNG 或 WebP；
   - 蓝湖导出分辨率；
   - 目标 Android density。
9. 点击“导入选中图片”。
10. 下载完成后，图片会进入下方“图片列表”。

支持的 Android density：

```text
mdpi
hdpi
xhdpi
xxhdpi
xxxhdpi
```

如果页面切图读取失败，插件会尽量回退到页面整图；如果某个设计稿或页面读取失败，其他设计稿仍会继续读取，并在结果中显示失败信息。

## 五、从图片或 ZIP 导入

如果蓝湖接口无法直接读取切图，可以先在蓝湖网页中下载图片或 ZIP，再使用文件导入。

1. 切换到“导入设置 → 文件导入”。
2. 导入单张或多张图片时，点击“选择图片…”。
3. 导入蓝湖下载包时，点击“选择 ZIP…”。
4. 支持的格式：
   - PNG
   - JPG
   - JPEG
   - WebP
5. ZIP 中如果包含以下目录，插件会尽量自动识别目标目录：

   ```text
   drawable-mdpi
   drawable-xxhdpi
   mipmap-xxhdpi
   xxhdpi
   ```

6. ZIP 根目录直接放图片也可以导入。
7. 如果 ZIP 路径和文件名无法识别 density，则使用“文件回退 density”，默认是 `xxhdpi`。
8. 导入后，所有图片会进入“图片列表”，可继续修改目标名称和目标资源目录。

ZIP 中的目录不要求只有一张图片。插件会逐个读取 ZIP 条目，并跳过不支持的文件或无效条目，同时保留其他有效图片。

## 六、选择资源根目录

“资源根目录”是 Android 资源目录的上级根目录，不是某一张图片最终写入的完整目录。

可以选择以下任一种：

```text
模块根目录
模块\src\main\res
模块\res
```

选择或填写后，插件会扫描其中已有的：

- `drawable-*`
- `mipmap-*`

例如：

```text
drawable-mdpi
drawable-zh-rCN-xxhdpi
drawable-night-xxhdpi-v21
mipmap-xxhdpi
```

这些目录会出现在图片列表和批量编辑的目标资源目录下拉框中。对应 density 的目录不存在时，插件会在处理时创建标准目录，例如 `drawable-xxhdpi`。

建议直接选择 Android 模块中的 `src\main\res`，这样最不容易选错层级。

## 七、检查和编辑图片列表

图片列表主要包含以下列：

| 列 | 作用 |
|---|---|
| 预览 | 图片缩略图预览；无法解析时显示占位符 |
| 原文件名 | 导入来源文件名 |
| 原始大小 | 原始文件大小 |
| 尺寸 | 图片像素尺寸 |
| 格式 | PNG、JPG、JPEG 或 WebP |
| 目标名称（可编辑） | 最终写入 Android 资源目录的文件名 |
| 目标资源目录（可编辑） | 最终写入的实际 `drawable-*` 或 `mipmap-*` 目录 |
| 导入工程 | 是否写入工程 |
| 需要压缩 | 是否先调用 Tinify 压缩 |

目标名称必须符合 Android 资源命名规则：

- 只允许小写字母；
- 允许数字；
- 允许下划线；
- 扩展名必须是 `png`、`jpg`、`jpeg` 或 `webp`；
- 不要使用空格、中文、短横线或大写字母。

插件会尽量将中文文件名转换为小写英文或拼音，但建议在写入前检查目标名称。

右键点击文本输入框可以使用剪切、复制、粘贴和全选。API Key 和 Cookie 输入框不提供复制操作，以降低敏感信息泄露风险。

### 批量编辑

1. 在表格中选择一行或多行。
2. 选择目标资源目录。
3. 点击“应用到选中行”或“应用到全部”。
4. 如需批量改名，输入名称前缀并执行批量改名。

批量修改目标资源目录会直接保存到每一行。最终写入时严格使用图片列表中该行保存的目录，不会因为默认 density 或资源根目录刷新而偷偷改回其他目录。

取消“导入工程”会排除该图片；取消“需要压缩”则直接写入原始文件，不需要 Tinify API Key。

## 八、执行处理和导入

1. 在“目标目录”中确认资源根目录。
2. 在图片列表中确认：
   - 需要导入的行已勾选“导入工程”；
   - 目标名称正确；
   - 目标资源目录正确；
   - 需要压缩的行已勾选“需要压缩”。
3. 点击“处理已导入图片”。
4. 插件会按批次处理图片并显示阶段和进度。
5. 压缩成功后，将压缩结果写入对应目录。
6. 未勾选压缩的图片直接写入原始字节。

如果 Tinify 请求失败，插件会显示失败信息，并根据界面选项决定是否回退使用原始文件。取消处理不会继续写入尚未处理的图片。

### 同名文件处理

如果目标路径已经存在，插件会逐项询问：

- 选择“是”：覆盖当前文件；
- 选择“否”：跳过当前文件并继续处理后续图片。

部分图片重名不会中断整批导入，最终状态会显示写入和跳过结果。

处理完成后，插件会刷新 IntelliJ/Android Studio 的虚拟文件系统，使新文件尽快出现在工程视图中。

## 九、常见问题

### 1. 蓝湖读取失败

依次检查：

- 浏览器中该链接是否可以正常打开；
- Cookie 是否从已登录且有权限的蓝湖请求中复制；
- Cookie 是否已经过期；
- 当前账号是否有团队和项目的导出权限；
- 单页面详情地址是否包含项目和团队参数；
- 是否误粘贴了 `blob:` 地址。

如果仍然失败，可以在蓝湖网页中下载图片或 ZIP，再使用“文件导入”。

### 2. ZIP 导入后 density 不正确

检查 ZIP 内部目录是否包含 `drawable-*`、`mipmap-*` 或标准 density 名称。如果目录层级比较特殊，直接在图片列表中修改“目标资源目录”，或调整“文件回退 density”后重新导入。

### 3. 图片列表有图片，但最终没有写入

检查：

- 该行是否勾选“导入工程”；
- 目标名称是否通过 Android 资源名校验；
- 资源根目录是否指向正确的 `res`；
- 目标资源目录是否为 `drawable-*` 或 `mipmap-*`；
- 同名文件询问时是否选择了跳过。

### 4. Tinify 压缩失败

检查 API Key 是否正确、账号是否还有额度，以及网络是否可以访问 `https://api.tinify.com`。不需要压缩的图片可以取消“需要压缩”，直接使用原始文件导入。

### 5. 为什么一次最多处理 20 张

插件按每批最多 20 张图片调用 Tinify，避免一次请求过大并方便显示进度。图片较多时，取消不需要压缩的图片，或分批执行。

## 十、安全提示

- 不要把 Tinify API Key 写入源代码、配置文件或 Git。
- 不要公开分享蓝湖 Cookie。
- Cookie 和 API Key 都使用 IntelliJ Platform `PasswordSafe` 保存。
- 插件日志不会输出 API Key、Cookie 或图片内容。
- 使用第三方压缩服务前，请确认图片内容符合你的组织和项目安全要求。
